CSLibrary2026 API Reference

Migration from the legacy library

What changed between the earlier CSLibrary implementations and this one.

The unified API

The earlier implementations exposed a different API per reader model and per communication stack. This library presents one API for every reader, and the model is only used when the connection is established.

// The legacy API was per model.
CSLibrary.RFIDReader cs108 = new CSLibrary.RFIDReader();
CSLibrary.CS710S.CS710RFIDReader cs710 = new CSLibrary.CS710S.CS710RFIDReader();

// The unified API is the same for every model.
var reader = new HighLevelInterface();
await reader.ConnectAsync(adapter, device, RFIDDEVICE.MODEL.CS710S);
RFIDReader rfid = reader.rfid;

Disconnect returns nothing

The most common difference when an application is ported.

-_ = reader.DisconnectAsync();   // legacy: Task<bool>
+reader.DisconnectAsync();           // current: void

The discovery API

The Bluetooth discovery moved to DeviceFinder and the TCP/IP discovery to NetFinder. Both are documented in Device discovery.

The radio options

The options of the radio are held in one object that is reached through reader.rfid.Options, instead of in the fields of the reader object.

// The legacy API kept the options in the reader.
reader.Options.TagRanging.bank1 = MemoryBank.USER;

// The unified API keeps them in the options object.
reader.rfid.Options.TagRanging.bank1 = MemoryBank.USER;

What to do when the application does not compile

The public API of this library is the source of truth: when an application fails to compile against it, adjust the application rather than the library signature.

See Getting started for the current API.
