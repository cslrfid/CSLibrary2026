CSLibrary2026 API Reference

The connection lifecycle

Closing a connection cleanly and releasing the resources that the reader holds.

Disconnecting

reader.DisconnectAsync();

The method picks the transport that the reader is using, so the same call works for Bluetooth LE and for TCP/IP.

The method returns nothing. The previous implementation of the library returned Task<bool>. Drop the discard when an application is ported:

-_ = reader.DisconnectAsync();   // previous API
+reader.DisconnectAsync();           // current API

What is released

  • the BLE connection is closed and the barcode scanner is powered off,
  • the TCP/IP connection is closed,
  • the internal timer that drives the command exchange is stopped,
  • the send buffer is cleared,
  • the reader state returns to DISCONNECT.

Removing the event handlers

The event handlers are not removed automatically, so an application that keeps the reader object alive should remove them itself.

reader.rfid.ClearEventHandler();      // all RFID events
reader.rfid.ClearOnAsyncCallback();      // only the inventory callback
reader.CancelEventOnReaderStateChanged(); // the connection state event

The reader object

A HighLevelInterface instance can be reused: connect it, disconnect it and connect it again. Dispose of it only when the application is finished with the reader.

The finalizer of HighLevelInterface closes the connection when the instance is garbage collected. Rely on DisconnectAsync() instead, so that the reader is released at a moment the application controls.
