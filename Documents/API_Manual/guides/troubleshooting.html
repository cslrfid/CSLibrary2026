Troubleshooting

The problems that come up most often, and what they mean.

The connection fails

Check the following in this order.

  • The reader is powered on and in range.
  • The application holds the Bluetooth permission of the platform. On Android the BLUETOOTH_SCAN and BLUETOOTH_CONNECT permissions are needed, on iOS the NSBluetoothAlwaysUsageDescription key of the application property list is needed.
  • The model that is passed to ConnectAsync matches the reader.
  • For TCP/IP the reader and the application are on the same network and the port is correct.

No tag arrives

  • The inventory was started: StartOperation(Operation.TAG_RANGING).
  • The options were set before the operation was started.
  • The country is set correctly: SetCountry("USA"). A reader that is set to the wrong region does not read the tags.
  • The power is high enough: SetPowerLevel(300).
  • The RSSI filter is not discarding every tag.
  • The application subscribed to OnAsyncCallback before the inventory was started.

The operation returns FAILURE

Most of the radio calls return Result.OK or Result.FAILURE. Result.FAILURE usually means that the reader model does not support the call, for example SetPostMatchCriteria is only implemented by the CS108.

Some calls always return Result.FAILURE even when they did their work. AntennaPortSetState is one of them: check the antenna port status instead of the return value.

The callback does not arrive

  • The event handler was removed by ClearEventHandler().
  • The handler was added after the operation was started.
  • The handler throws an exception: an exception in a callback handler stops the callback, so the following tags are not delivered.

The application freezes

The callbacks are raised on a background thread. If the handler does slow work the reader cannot send the next packet and the inventory slows down. Move the work to your own thread.

The reader is not found by the search

  • The Bluetooth search finds the reader but the name does not identify the model; the name is used to fill DeviceInformation.DeviceType.
  • A TCP/IP reader announces itself with a UDP broadcast, which does not cross a router. The application must be on the same subnet.

Getting the reader information

Console.WriteLine($"Model   : {reader.rfid.GetModel()}");
Console.WriteLine($"Country : {reader.rfid.GetCurrentCountry()}");
Console.WriteLine($"Firmware: {reader.rfid.GetFirmwareVersionString()}");
Console.WriteLine($"Power   : {reader.rfid.SelectedPowerLevel}");
Console.WriteLine($"Ports   : {reader.rfid.GetAntennaPort()}");

See Constants and enumerations for the result codes and Event reference for the callback payloads.
