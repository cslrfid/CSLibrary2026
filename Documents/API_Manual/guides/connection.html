CSLibrary2026 API Reference

Connecting to a reader

The two connection methods and what happens after the connection is established.

The two connection methods

MethodDescription
Task<bool> ConnectAsync(IAdapter adapter, IDevice device, RFIDDEVICE.MODEL deviceType) Connects to a reader over Bluetooth LE. The model tells the library which command set the reader uses.
Task<bool> ConnectAsync(string ipAddress, int port) Connects to a fixed reader over TCP/IP.

Bluetooth LE

bool connected = await reader.ConnectAsync(adapter, device, RFIDDEVICE.MODEL.CS710S);
if (!connected)
{
    // The reader refused the connection or is out of range.
}

The MODEL value selects the command set of the reader. Use RFIDDEVICE.MODEL.CS108 for the CS108, the CS468 and the other Rx000 based readers, and RFIDDEVICE.MODEL.CS710S for the CS710S and the CS203XL.

TCP/IP

bool connected = await reader.ConnectAsync("192.168.1.100", 2000);

What happens during the connection

When the connection succeeds the library performs the hardware initialisation:

  • the barcode scanner is powered on,
  • the RFID radio is powered off and on again so that it starts from a known state,
  • the Bluetooth controller and the reader hardware are queried,
  • the radio is configured for the connected reader model,
  • the battery reporting is enabled.

The OnReaderStateChanged event is raised with ReaderCallbackType.CONNECT_SUCESS when the reader is ready.

The reader state

reader.Status reports the state of the connection.

ValueDescription
READERSTATE.DISCONNECTThe reader is not connected.
READERSTATE.IDLEThe reader is connected and ready.
READERSTATE.BUSYThe reader is executing an operation.
READERSTATE.READYFORDISCONNECTThe connection was lost or is being closed.

Losing the connection

When the reader goes out of range the library raises OnReaderStateChanged with ReaderCallbackType.CONNECTION_LOST and puts the reader into the DISCONNECT state. The application decides whether to reconnect.

Only one connection is active at a time. Call DisconnectAsync() before connecting the same instance to another reader.

See The connection lifecycle for the cleanup rules and Device discovery for finding a reader.
